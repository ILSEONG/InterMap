# 사용자가 늘 때 손볼 것 (아키텍처)

서버 사양을 올리는 것 말고, 구조에서 고쳐야 할 것들을 모아 둔다. 2026-11-13에 코드 기준으로 점검했고, 그날 할 수 있는 것은 반영했다.
새로 발견한 것은 여기에 추가하고, 끝낸 것은 "한 것"으로 옮긴다.

지금 구성: Render 웹 서비스 1대(Spring Boot) + Neon PostgreSQL + Vercel(웹) + 안드로이드/iOS 앱(Capacitor).

## 한눈에

| # | 항목 | 상태 | 막히는 이유 / 다음 할 일 |
|---|---|---|---|
| 1 | 후기 목록 조회 | **일부 완료** | DB에서 걸러 읽게 바꿈. 지도 범위·기간으로 잘라 받기는 남음 |
| 2 | 사진을 DB에 저장 | 남음 | 오브젝트 스토리지 계정(Cloudflare R2 등)이 필요 |
| 3 | 서버 메모리에 든 상태 | **완료** | 인증번호·로그인 진행 상태·횟수 제한을 DB로 |

| 8 | 서버 여러 대로 늘리기 | 남음 | 3번이 끝나 전제는 갖춤. 예약 작업 중복 실행 방지가 남음 |

## 한 것 (2026-11-13)

### 1. 후기 목록 조회 — `GET /api/reviews`
- 전에는 요청마다 **전체 후기 + 전체 사진 목록**을 읽어 와 서버 메모리에서 "내가 볼 수 있는 것"만 걸렀다. 남의 후기가 쌓일수록 모든 사람의 조회가 느려지는 구조였다.
- 지금은 볼 수 있는 작성자 id(나·팔로우한 사람·주인장)로 DB에서 바로 읽는다. 사진·프로필 사진은 내려줄 후기 것만 읽고, 가게 좌표는 가게마다 조회하던 것(N+1)을 상호로 한 번에 읽는다.
- 코드: `review/ReviewController.list`, `review/ReviewAudience.visibleAuthorIds`

### 3. 서버 메모리에 든 상태 → DB
- 이메일 인증번호와 틀린 횟수, 비밀번호 틀린 횟수(잠금), 하루 한도, 소셜 가입·연결 티켓, 간편 로그인 진행 상태가 `ConcurrentHashMap`에 있었다. 서버가 다시 켜지면(재배포, 무료 서버가 잠들었다 깰 때) 전부 사라졌고, 서버를 두 대로 늘릴 수도 없었다.
- 지금은 DB 표 `server_state`에 만료 시각과 함께 둔다. 키는 SHA-256으로 저장해 이메일·IP가 표에 남지 않는다.
- 코드: `state/ServerState`

### 5. 바깥 서비스 호출 타임아웃
- 메일(Brevo)·푸시(FCM)·간편 로그인·문자 호출에 타임아웃이 없어서, 상대가 응답 없이 멈추면 요청 스레드가 끝없이 묶였다. 연결 5초 / 응답 15초를 걸었다.
- 코드: `web/Http`

### 6. 인덱스
- `review(author_id, created_at)`, `review(restaurant_name)`, `review_photo(review_id)`, `review_comment(review_id)`, `review_comment(author_id)`, `follow(followee_id)`, `follow_request(target_id)`, `push_token(user_id)`, `favorite(user_id)`. PostgreSQL은 외래키 칸에 인덱스를 자동으로 만들지 않는다.
- 가게·닉네임 검색(가운데 포함 `LIKE '%검색어%'`)용 trigram(GIN) 인덱스. 서버 시작 때 만든다(`auth/SchemaPatch`). **검색어가 3글자 이상일 때만 듣는다.**

### 7. 관측 — 마이페이지 → 서버 상태
- 운영 관리자 계정으로 로그인하면 마이페이지에 "서버 상태"가 보인다: 요청 수·오류·응답 시간, 시간대별 요청, 시간을 많이 쓰는 API, 바깥 서비스(메일·푸시·간편 로그인) 성공/실패와 마지막 오류, 최근 경고·오류 로그, 회원·후기 수와 DB 용량.
- 운영 관리자는 환경변수 `ADMIN_EMAILS`(쉼표로 구분한 이메일)로 정한다. 저장소가 공개라 이메일은 코드에 적지 않는다.
- 요청·오류 통계는 **서버 메모리에 있어 서버가 다시 켜지면 0부터 다시 센다.**
- 코드: `ops/`, 프론트 `components/AdminOps.tsx`

## 남은 것

### 2. 사진을 오브젝트 스토리지로 (우선순위 높음)
- 지금: 후기 사진과 프로필 사진이 DB에 `bytea`로 들어 있다. 사진 한 장을 볼 때마다 앱 서버와 DB 연결을 거치고, DB 용량의 대부분을 사진이 차지한다 (서버 상태 화면의 "DB 용량 / 그중 사진"으로 확인).
- 할 일: Cloudflare R2(무료 10GB, 내려받기 요금 없음) 같은 오브젝트 스토리지에 올리고 DB에는 주소만 둔다. 기존 사진을 옮기는 일회성 작업과, 사진 주소에 들어가는 추측 불가 키(`ReviewPhoto.accessKey`) 방식을 유지하는 방법을 같이 정해야 한다.
- 필요한 것: R2 계정과 키(환경변수). 이게 없어 아직 못 했다.
- 신호: DB 용량이 요금제 한도의 절반을 넘을 때.

### 1-나머지. 후기를 잘라 받기
- 지금: 한 사람이 볼 수 있는 후기를 **전부** 한 번에 내려준다. 프론트가 받아서 가게별·작성자별로 나눈다.
- 할 일: 지도 범위(bbox)·기간·페이지 단위로 받게 API와 프론트를 같이 바꾼다. 스토리·팔로잉 현황·프로필이 모두 이 목록을 쓰므로 화면별로 필요한 조회를 따로 나눠야 한다.
- 댓글 목록(`GET /api/comments`)도 볼 수 있는 댓글을 전부 내려준다 — 후기 id로 잘라 받게.
- 신호: 한 사람이 보는 후기가 수천 건을 넘거나, 서버 상태 화면에서 `GET /api/reviews`의 p95가 1초를 넘을 때.

### 4. 알림을 표로
- 지금: 앱마다 60초에 한 번 알림을 묻고, 서버는 그때마다 댓글·팔로우 표를 뒤져 최근 30일 알림을 계산한다. 접속자 수만큼 분당 쿼리가 는다.
- 할 일: 이벤트가 생길 때 알림 표에 한 줄 쓰고, 조회는 그 표만 읽는다. 안 읽은 개수는 가벼운 쿼리 하나로. 푸시가 왔을 때만 새로 받게 하면 폴링 주기를 늘리거나 없앨 수 있다.
- 같이 볼 것: 알림·팔로우 목록·댓글 목록·신고 화면이 프로필 사진 주소를 붙일 때 **전체 회원의** 프로필 사진 목록을 읽는다(`UserAvatarRepository.urlsByUserId()`). 후기 목록처럼 필요한 사람 것만 읽게 바꿀 것.

### 5-나머지. 작업 큐와 재시도
- 지금: 푸시는 서버 안 스레드 하나로 보내고(서버가 죽으면 보내던 것은 사라진다), 인증번호 메일은 요청을 처리하는 중에 바로 보낸다(메일 서비스가 막히면 가입이 멈춘다).
- 할 일: 보낼 일을 DB 표에 쌓고 워커가 꺼내 보내며 실패하면 재시도한다. 처음엔 DB 표 기반으로 충분하다.
- 2026-11-13 사례: Brevo가 처음 보는 IP의 API 요청을 막아(재배포로 서버 IP가 바뀜) 인증번호 발송이 전부 실패했다. Brevo 보안 설정에서 API 키의 IP 차단을 꺼서 풀었다. 서버 상태 화면의 "바깥 서비스"에 이런 실패가 바로 보인다.

### 6-나머지. 검색
- 2글자 검색("김밥", "스벅")은 trigram 인덱스를 못 타서 가게 표 전체를 훑는다. 한글 검색은 2글자가 많다.
- 할 일: 2글자용 bigram 인덱스(PostgreSQL 확장 `pg_bigm` — 호스팅이 지원하는지 확인)나, 검색 전용 칸(초성·공백 제거 등)을 따로 두는 방법.

### 7-나머지. 관측
- 통계가 메모리에만 있어 서버가 다시 켜지면 사라진다. 지난주와 비교할 수 없다.
- 문제가 생겨도 누가 화면을 열어 봐야 안다. 오류율이 오르거나 바깥 서비스가 연속으로 실패하면 운영 관리자에게 푸시·메일을 보내게.
- 외부 도구(Sentry, 가동 체크 서비스)를 붙이는 것도 방법.

### 8. 서버를 여러 대로
- 3번이 끝나 로그인·인증 상태는 서버 사이에 공유된다. 남은 걸림돌:
  - 예약 작업(`@Scheduled` — 투표 정리, 인허가 상태 동기화, 만료 상태 정리)이 서버마다 한 번씩 돈다. 한 대만 돌게 잠금(DB 행 잠금이나 ShedLock)이 필요하다.
  - 요청 통계(7번)가 서버마다 따로 쌓인다.
  - DB 연결 수: 서버 대수 × 풀 크기가 Neon 한도를 넘지 않게, 필요하면 Neon의 연결 풀러(pgbouncer) 주소를 쓴다.

## 운영 메모
- 운영 관리자 추가: Render 환경변수 `ADMIN_EMAILS`에 이메일을 쉼표로 이어 넣고 재배포.
- Render 무료 서버는 한동안 요청이 없으면 잠들고, 깨어날 때 첫 요청이 오래 걸린다. 서버 상태 화면의 "서버가 켜진 지"가 자주 짧게 보이면 이 때문이다.
