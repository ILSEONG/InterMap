# 보안 메모

지금 들어가 있는 방어와, 코드 밖에서 사람이 챙겨야 하는 것을 적어 둔다. 새로 막은 게 생기면 여기에 한 줄 더한다.

## 코드에 들어가 있는 것

**로그인·계정**
- 로그인은 서버가 기억하는 임의 토큰 방식 (JWT·쿠키 아님). DB에는 토큰의 해시만 둔다. 서버에서 지우면 즉시 무효.
- 로그인은 기기별 (`auth_session`). 처음 보는 기기에서 로그인하면 먼저 쓰던 기기에 푸시와 알림이 간다. 마이페이지 "다른 기기 로그아웃"으로 전부 끊을 수 있다.
- 비밀번호는 BCrypt. 5번 틀리면 계정 잠금(일정 시간), 인증번호는 5번 틀리면 폐기, 재발송 간격·하루 발송 한도 있음.
- 소셜 로그인은 state·verifier로 시작한 기기에서만 결과를 받는다. Apple은 서명 검증된 토큰 교환만 믿는다.
- 탈퇴는 방금 로그인한 세션만 받는다 (새어 나간 토큰 하나로 계정을 못 지우게).

**요청 제한 (`web/RequestGuard`)**
- IP별 분당 600건, 로그인·가입·인증번호 쪽은 분당 30건. 넘으면 429. 걸리면 서버 상태 화면의 경고 로그에 남는다.
- JSON 본문 256KB 초과 거절. 사진은 장당 1MB, 요청당 10장.
- 후기·댓글·사진·투표는 사람별 하루 한도가 따로 있다 (`DailyLimits`).

**입력·출력**
- 사진·프로필은 파일 앞 바이트로 실제 이미지인지 확인하고, 내려줄 때 형식 추측 금지 헤더를 붙인다.
- 화면에 넣는 글은 React가 이스케이프한다. 지도 핀처럼 HTML 문자열을 직접 만드는 곳은 `escapeHtml`을 거친다.
- DB 쿼리는 전부 바인딩 파라미터.

**응답 헤더**
- 서버: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, HTTPS 고정(HSTS), API 응답은 CSP `default-src 'none'`.
- 웹(Vercel, `frontend/vercel.json`): 같은 헤더 + 다른 사이트 틀 안에 못 넣게(`frame-ancestors 'none'`).

## 사람이 챙길 것 (코드로 못 하는 것)

- **비밀값은 Render 환경변수·GitHub Secrets에만.** 저장소가 공개라 코드·커밋·이슈에 한 번 올라가면 지워도 남는다. 올라갔다면 그 값은 바로 폐기하고 새로 발급.
- **GitHub**: 계정 2단계 인증, 저장소 Settings → Code security에서 Secret scanning·Push protection·Dependabot alerts 켜기, main 브랜치 보호(직접 push 금지).
- **Render·Supabase·Cloudflare·Brevo·Google·Apple·Naver·Kakao 계정**: 전부 2단계 인증. 관리자 비밀번호(`ADMIN_PASSWORD`)는 다른 곳에서 쓰는 것과 겹치지 않게.
- **Supabase DB**: 접속 주소(`JDBC_URL`)가 새면 DB 전체가 열린다. 의심되면 Supabase에서 비밀번호를 재설정하고 Render 값을 바꾼다. Data API는 꺼 둔다(서버가 DB에 직접 붙으므로 필요 없다). 무료 플랜은 자동 백업이 없다 — `pg_dump`로 직접 받아 둔다.
- **서버 상태 화면**을 가끔 열어 "요청 제한에 걸림" 경고와 로그인 실패가 몰리는지 본다.

## 아직 안 한 것

- 웹 CSP로 스크립트 출처까지 제한하기 — 네이버 지도 SDK가 쓰는 주소를 전부 확인한 뒤에 걸어야 지도가 안 깨진다.
- 오류율·제한 초과가 치솟을 때 운영자에게 자동 알림 (지금은 화면을 열어 봐야 안다 — `scaling.md` 7번).
- 서버가 여러 대가 되면 요청 제한을 공유 저장소로 (지금은 서버마다 따로 센다).
